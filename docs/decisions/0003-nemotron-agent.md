# 3. A model plans, but only checked tools touch the fleet

The operator talks in sentences and Nemotron turns them into missions. A language model is slow, can be down, and can be talked into things, so the design assumes each of those happens during a flight.

- **Stop words skip the model.** `safety_command` runs first and has no network path. Stop, hold, land and E-stop work while the model is hung. It trims filler and repeats from the ends of a sentence, but the rest must still match, so "don't stop" and "stop mapping" don't fire.
- **The model has no E-stop, sticks or coordinates.** It names a kind of work and a region. Regions are computed from the fence, so a valid call can't point outside it. Anything else comes back as a sentence the model can repeat.
- **A stop outranks a thought in progress.** A stop command raises an epoch before it takes the flight lock. A turn that started earlier sees the new epoch and drops its answer. If its call is already running, the stop ends what it started.
- **Leaving the ground needs a person.** A takeoff, or a mission with nothing flying, becomes a plan with an id. Nothing in the model's path can approve it. Approval checks everything again, since the fleet may have changed, and an unapproved plan expires after 5 minutes.
- **The operator picks the region, in code.** Prompt rules alone let the model answer "focus on the other side" by choosing south. The tool check now refuses a region that isn't in the operator's words or the sentence before, allowing for speech to text. Starting on the whole room is the default and needs no naming.
- **The model's report is checked too.** After a refused start, the model once said a plan was ready to approve. A turn where every action was refused can't claim progress, so the tools' own words replace it. Past tool calls also stay in the history: with only earlier replies to read, the model copied them and claimed a search had started without calling anything.
- **Events can't launch anything.** A mission event may get a short model update, at most one every 30 s. Those turns get read tools and `focus_region`, and turns with a finding get read tools only, because a finding's words came from another model.
- **Thinking off on Ultra.** With thinking on and an earlier prompt, Ultra asked for clarification on the pitch sentence "Inspect these things for damage", passed 46 of 48 sentences and had a median of 3.5 s a sentence. With it off, the first run passed 86 of 87 at 2.6 s. Lightning is the fallback and scored lower on safety items (43 of 45), which matters less because the tools check every call whichever model sent it.
- **An unknown inspect target flies the region.** `MissionManager` refuses a name it hasn't seen, and after an approved takeoff that would leave the fleet hovering with no mission. The tool checks the memory first, drops the name and says so.
- **Plain `urllib`, one client per process.** It paces itself at 36 requests a minute per model, under NVIDIA's limit of about 40.
